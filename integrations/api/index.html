  • ✓ Безопасная авторизация OAuth 2.0: выдача временных Bearer JWT-токенов по паре Account / Secure password.

  • ✓ Высокая производительность: гарантированная обработка нагрузки до 200 запросов в секунду (RPS).

Частые вопросы разработчиков и решение ошибок (Troubleshooting)

Почему метод создания заказа вернул HTTP 202 ACCEPTED, но заказ не появился в системе?

Статус ACCEPTED означает, что запрос принят очередью и прошел базовую синтаксическую проверку[cite: 20]. Полная валидация выполняется асинхронно[cite: 20]. Для получения номера накладной (cdek_number) или списка ошибок (errors) вызовите метод GET /v2/orders/{uuid} через 2–3 секунды[cite: 20].

Ошибка «shipment location is not recognized» или «recipient location is not recognized»

Не удалось однозначно определить населенный пункт[cite: 20]. Рекомендуется передавать локацию по уникальному коду города СДЭК (code) либо по связке: уникальный идентификатор ФИАС (fias_guid) / почтовый индекс + название города[cite: 20].

Ошибка «error_validate_im_dep_number_has_already_had_integration»

Номер отправления в системе интернет-магазина (number) не уникален в рамках вашего договора[cite: 20]. В системе СДЭК уже зарегистрирован активный заказ с таким идентификатором[cite: 20]. Передайте уникальный номер заказа[cite: 20].

Почему при создании заказа от двери курьер не приезжает автоматически?

Создание накладной и вызов курьера на забор груза — это два независимых процесса[cite: 20]. Для забора посылок с вашего склада необходимо вызвать метод регистрации заявки на забор груза (POST /v2/intakes)[cite: 20].

Какие требования предъявляются к серверу для приема Webhooks?

Ваш эндпоинт должен быть доступен по HTTPS и возвращать статус HTTP 200 OK в течение 15 секунд[cite: 20]. При систематических таймаутах (более 12 неудачных попыток за 75 минут) подписка временно блокируется системой[cite: 20].
